# Session lifecycle для WSS

`sessionstate` — чистая модель protocol §3/§8 и lifecycle из ТЗ 3.21. Она объединяет регистрацию, status/readiness, drain/unregister/reconnect и [`wssstate`](../wssstate/README.md) с общими HTTP/WS IDs, budget и cancel ledger. Нет sockets, goroutines, таймеров, callback execution, credentials verification, registry или durable storage. Это ещё не прикладной `client` и не transport adapter; публичные thread-safe Run/Close/WaitReady остаются будущей работой.

## Вызовы адаптера

1. Создать `New(Config)` с ролью Gateway/Service, исходным control limit, registration timeout ≤10s, MaxCommands 1…2048 и MaxPendingCancels 1…2048. Production — default; Development разрешает null credential expiry по существующему wire-контракту.
2. После TLS/credential exchange вызвать `Begin(now)` для нового транспорта. Connect/TLS timeout и retry backoff находятся снаружи. New ничего не запускает. Begin запрещён при живом транспорте, до cleanup старого или после окончательного Closed.
3. Передавать декодированные значения в `Apply(sender, message, now)` до доставки и непосредственно перед ordered transmission. Входящие frames ограничивать до allocation. На Gateway перед исходящим register_ack вызвать `AuthorizeRegistration`: это явное утверждение вызывающего слоя об успешных identity/permissions/conflicts/durable control/outbox проверках. Модель их не выполняет. Ack сверяется с сохранённой bounded deep copy исходного register.
4. Вызывать `Security(ready, absoluteDeadline, now)` с проверенной локальной security готовностью. Ready по умолчанию false; deadline только сокращается. Revoke немедленно закрывает старую session без graceful grace. Credential expiry и ready_not_before берутся из ack; transmitted ObservedAt не участвует в freshness. Caller предоставляет монотонный now и корректное доверенное wall time для Unix timestamps.
5. На Service при настроенном callback вызывать StartProbe/FinishProbe вокруг фактического вызова. StartProbe резервирует один слот; FinishProbe применяет negotiated consecutive thresholds. Просроченный результат по readiness.stale_after_ms снимает готовность и требует новых consecutive successes. Timeout снимает readiness немедленно, но удерживает слот до завершения invocation; поздний success не восстанавливает готовность. Сам callback, его context cancellation, interval scheduling и запрет вызова под пользовательским mutex реализует adapter. Gateway использует готовый status Service и собственную security gate.
6. Вызывать `Advance(now)` по таймеру и без трафика: registration/security/drain/cancel deadlines, probe timeout и status freshness требуют движения времени. Snapshot.StatusDue сообщает Service о необходимости отправить первый/периодический/изменившийся status. Advance не отправляет его автоматически. ProbeDeadline/ProbeOutstanding позволяют обслуживать и диагностировать callback. Snapshot не двигает время.
7. Исполнять Effect даже при ошибке. Stream содержит эффекты wssstate; Reply (drain_ack) применить через Apply перед ordered write. StopAll отменяет все контексты старой session, включая readiness callback. CloseTransport закрывает transport; CleanupRequired требует освобождения принадлежащих adapter ресурсов. После подтверждённого закрытия/cleanup и завершения callback вызвать Cleaned. Только затем разрешён Begin следующего соединения. При фактическом transport failure вызвать Disconnected(retry, now). Ни один запрос, chunk или business operation не переносится в новое соединение.

Все методы вызываются одним владельцем последовательно. Ошибки локальных frames не меняют wire state; Advance перед операцией всё равно применяет наступившие deadlines/readiness изменения. Некорректный frame peer завершает session и возвращает cleanup effect. ErrBodyLength от stream state сохраняет изоляцию одного stream; adapter исполняет StopScope и cancel по README wssstate. Ошибка частичной записи требует Disconnected и закрытия транспорта.

## Admission и закрытие

Registered отличается от Ready. Gateway назначает новые streams только в Ready: свежий status ready, завершённый recovery barrier и проверенная security readiness. Status sequence строго возрастает, не оборачивается; stale считается по elapsed от receipt, граница stale_after включительна, затем Registered. Standby/route activation в эту модель не входят. Выбор активных маршрутов и permissions проверяет gateway registry.

Service после собственной потери readiness ещё может получить start, ранее записанный Gateway. После первой готовности модель допускает такие входящие starts до drain fence при сохранённой security gate; это не разрешение Gateway назначать новые requests при not-ready. До первой готовности/при security recovery starts запрещены. Уже активные потоки продолжаются при обычной потере readiness; deadlines/revoke действуют отдельно.

При drain Gateway немедленно прекращает новые назначения. Service-origin drain допускает пересекающиеся ранее записанные starts до входящего Gateway drain_ack. Gateway-origin drain/reconnect уже находится после prior starts в его ordered writer и сразу fence-ит Service. После fence новые HTTP/WS starts запрещены; existing frames/Consume/cancel продолжаются. Одновременные drain требуют обоих ack. Unregister допустим после drain/fence, всех drain ack и освобождения активных потоков, включая unconsumed bytes и pending cancel. На Gateway исходящий unregister_ack требует ConfirmExcluded — явного подтверждения фактического исключения session и cleanup. Durable route ownership не удаляется.

Command IDs хранятся в bounded session-local history до конца транспорта: повтор/reuse, unsolicited/mismatched/duplicate ack запрещены; ID не является monotonic counter. History учитывает обоих отправителей в общей namespace; новых записей больше MaxCommands не выделяется. Reconnect не имеет отдельного ack по wire-контракту: bounded drain заканчивается unregister/ack либо deadline. Новый session ID должен отличаться от непосредственно предыдущего; генерация случайных tokens и проверка исторической уникальности принадлежат registration layer.

Close — окончательное локальное shutdown intent. Close без более раннего срока ограничен 30s и negotiated drain minimum. Повторные Close/команды только сокращают deadline; минимум включает negotiated drain, parent/security и credential expiry. Close во время credential rotation подавляет reconnect. Registration timeout не включает ожидание ready_not_before. При deadline active HTTP/WS прекращаются через StopAll/CloseTransport; модель не обещает остановить игнорирующий context пользовательский код. Незавершённый callback блокирует новый reconnect, не создаёт новые invocation.

## Память и проверки

После ack из negotiated buffer_bytes сначала вычитается `MaxCommands × 128` bytes под prepaid command-map capacity, остаток передаётся wssstate. Snapshot.ReservedBytes включает обе модели. Command history не освобождает свой фиксированный резерв до завершения транспорта. Register хранится в bounded deep copy до ack; предрегистрационный buffer и реальные transport/control queues/handler allocations требуют отдельных квот adapter. Snapshot accounting не измеряет RSS и не доказывает actual handler cleanup.

Tests используют fake time, обе роли и неизменённый golden register/ack. Проверяются registration/security/barrier, sequence/stale, callback thresholds/timeout/slot across disconnect, drain races/fences, HTTP/WS completion/Consume, simultaneous ack, unregister cleanup, deadlines/rotation/revoke, bounded history и новая namespace. FuzzSessionLifecycle проверяет обе стороны с отложенной доставкой prior start через Service-origin drain и окончательным освобождением модели. Unit/model-проверки не заменяют transport integration или native Windows runtime acceptance.
