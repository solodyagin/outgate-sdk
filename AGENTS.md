# Правила разработки Outgate SDK

- Модуль — `github.com/solodyagin/outgate-sdk`, repository — https://github.com/solodyagin/outgate-sdk.
- Начните с [карты контекста](docs/context-map.md): читайте относящиеся к задаче разделы ТЗ/protocol, локальных schema и код с тестами. Production имеет приоритет. Карта — навигация, не замена нормативного контракта; текущее состояние реализации не хранится в инструкциях.
- Перед продолжением прочитайте «Точку продолжения» в `../project-notes/implementation-status.md`, сверьте с кодом/Git. После завершённого шага и перед остановкой обновите задачу, результат, незавершённое, проверки текущей сессии, блокеры и следующий шаг. Историю читайте по ссылкам при необходимости; не дублируйте её и не создавайте отдельный changelog точки продолжения.
- Общий статус gateway/SDK/template находится только в `../project-notes/implementation-status.md`, вне repositories компонентов; не включайте его в их коммиты. Если файла нет, сообщите и восстановите контекст по коду/Git, не создавая статус в компоненте.
- Не публикуйте реальные домашние каталоги, персональные пути и расположение локальных резервных копий, включая документы, отчёты проверок и сообщения коммитов. Используйте относительные пути, ссылки на repositories и явные нейтральные placeholders (`<user>`, `${USER}`, `<temporary-directory>`). Конкретные временные пути заменяйте описанием назначения файла; системные пути и переносимые примеры команд допустимы.
- Код самостоятельный: reverst imports, транзитивные зависимости, vendoring, копирование/адаптация его исходников и запуск reverst как обязательного инструмента запрещены. SDK не импортирует gateway.
- `protocol/v1` содержит только wire types/codecs/чистые helpers; не зависит от `client`, транспортных библиотек, sockets, SQL, RBAC или хранилищ.
- Публичные codecs не подтверждают аутентификацию, авторизацию, flow-control budget или session state. Не называйте framing полноценным adapter.
- Production по умолчанию, fail closed: без автоматического transport/security fallback, InsecureSkipVerify, фиктивных identity и логирования credentials. Ограничивайте размеры до выделения памяти; не буферизуйте целиком HTTP body. После начала передачи запроса business retry запрещён для любого метода. Не применяйте path.Clean и повторный URI decode.
- Не начинайте QUIC adapter до сквозного spike напрямую на quic-go: reverse HTTP/3, stream 0 exclusion, streaming/cancel, internal CONNECT, native Linux/Windows. Самодельный framing не заменяет HTTP/3.
- Нормативные schema/fixtures принадлежат gateway repository. Локальные `docs/protocol.schema.json` и `tests/fixtures/protocol/v1/` — побайтовый snapshot (см. `docs/contract-snapshot.md`); тесты не требуют gateway checkout. Wire-изменения синхронно обновляют ТЗ, protocol/schema, golden fixtures и тесты обоих repositories. Не исправляйте fixtures ради прохождения реализации.
- [Обязательные проверки и прямые команды](docs/checks.md): `python3 -B tests/check.py package ./delivery` — целевые; `contracts` — fixtures; `full` — полный локальный набор. Целевые проверки не заменяют итоговые; Windows compile, parser/fuzz и синхронизация snapshots выполняются отдельно по области изменения. В ответе достаточно области, результата и ограничений; полные логи оставляйте для диагностики. Не повторяйте успешные проверки без новых изменений или неразрешённой неопределённости.
- Не создавайте обязательный go.work/локальные replace. Standard-library-only части проверяются без registry (`GOPROXY=off`). Для новых dependencies фиксируйте версии, проверяйте совместимость, безопасность, лицензии и SBOM.
